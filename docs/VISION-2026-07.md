# Hearthmind — Long-Term Design Vision Roadmap (July 2026)

Status: **design only — nothing in this document is implemented yet.**
This is the mandated codebase audit + implementation roadmap for the
user's long-term design vision ("living civilization simulator",
"maximize emergence per LLM call", two-layer engine, hierarchical
intelligence, Town Consciousness, Narrative Direction). The vision text
itself was delivered in chat (2026-07-16); this document maps it onto
the existing codebase and sequences the work. CLAUDE.md carries the
compact standing summary; this file is the full detail.

Everything here honors the existing "Preserve absolutely" list:
single-writer tick loop + queued interventions, fallback-on-every-LLM-
call liveness, objective/subjective state split, Phase G ambiguity
discipline, constants-with-rationale + decision log, two-surface UI.

---

## 1. Audit: vision vs. what already exists

The central audit finding: **the vision is not a pivot — it is the
codebase's own trajectory, extended.** Roughly 60% of the vision's
named systems already exist in at least a v1; almost every gap is an
extension of an existing store or job, not a parallel implementation.
The architecture the vision demands (deterministic substrate + LLM
cognition, core cast, layered update frequencies, event-driven
interacting systems) is already this engine's shape.

### 1.3 What must NOT be duplicated (extend instead)

- **Job scheduling**: every new LLM job = one more entry in the
  engine's `_maybe_schedule_*` registry + its own `MONTHLY_JOB_DAY`
  slot (standing rule: never `month_end`). No new scheduler.
- **Belief storage**: religion tenets, ideology, faction identity all
  reuse the `beliefs` list shape (+ institution mirroring), not new
  parallel stores.
- **Phase G channels**: Town Consciousness v2 *is* Phase G extended —
  temperament, omens, player_standing, whisper folding are its limbs,
  not things to rebuild.
- **Bounded-walk math**: settlement mood axes reuse
  `bounded_random_walk_step` (native module 12) with event-driven
  nudges, exactly like temperament.
- **Culture lists**: rituals are a new *kind* within the existing
  capped tradition/festival machinery, not a new subsystem.
- **Fallbacks**: every new LLM decision point ships with a
  deterministic fallback from day one (liveness rule, unchanged).

## 2. Conflicts with standing rules — flagged, not silently resolved

1. **Core cast size**: vision says "~11"; tuned default is 14
   (v0.72.4, live-hardware-derived). Proposal: keep 14 as the tuned
   default — "~11" reads as an order-of-magnitude intent, and the CLI
   lever already exists. Flag to user if they want literal 11.
2. **"Town Consciousness may directly cause events"** vs. Phase G's
   permanent "never escalate toward anything explicit". Proposal:
   direct causation is allowed **only through channels that always
   have a mundane explanation available** (the existing omen rule,
   generalized): weather nudges within the model's realized range,
   dream symbols, false memories, misplaced-object events, probability
   nudges (temperament-style). Never an event a player could only
   read as supernatural. This satisfies both texts; treated as the
   governing interpretation unless the user overrides.
3. **"Psychological horror"** (FROM/Higurashi): compatible with Phase G
   ambiguity — fear from uncertainty, not monsters. No new rule needed;
   the ambiguity discipline *is* the horror mechanism.
4. **No unit tests**: unchanged. Verification = ad-hoc scripts + live
   reports, per workflow rules, for every phase below.

## 3. LLM budget arithmetic (the constraint that shapes everything)

Standing rules: per-agent/per-pair jobs are core-cast-gated; everything
counts against `llm_max_calls_per_day` (320); measured baseline ~11.5
calls/sim-day at cast 14. Additions proposed by the full roadmap:

| New job | Cadence | Est. calls/sim-day |
|---|---|---|
| Reflect() | weekly per core agent | 14/7 ≈ 2.0 |
| Dream() | monthly per core agent | 14/30 ≈ 0.5 |
| InterpretRumor() | on rumor passing a core agent, capped | ≤ 2.0 |
| Folklore condensation | monthly per settlement | ≈ 0.03 |
| Settlement mood interpretation | monthly | ≈ 0.03 |
| Narrative themes | quarterly | ≈ 0.01 |
| Ritual/religion formation | seasonal, gated | ≈ 0.01 |
| Faction framing | rare (threshold-gated) | ≈ 0.01 |
| Town Consciousness v2 | monthly | ≈ 0.03 |

Total: **≈ +4.6/day → ~16/day**, 5% of the ceiling. The whole vision
fits inside the existing budget with an order of magnitude to spare.
"Maximize emergence per call" is achieved structurally: deterministic
state (emotions, mood, reputation, rumor mutation flags) accumulates
for free and is *read* by the few calls that fire.

## 4. Roadmap — phases I through N

Sequencing logic: deterministic substrate first (cheap, feeds every
prompt), then minds, then information/story (needs the memory layers),
then society (reads reputation/factions), then meaning
(religion/themes, reads folklore), and the Town Consciousness last
(it manipulates every channel the earlier phases build). Each phase is
a shippable milestone in the existing one-coherent-milestone-at-a-time
discipline. Persistence: every new field gets `to_dict`/`from_dict`
round-trip + legacy-snapshot defaults on first landing.

### Phase I — Inner Life (deterministic; ~zero LLM cost) — SHIPPED v0.76.1-v0.76.3

The highest-leverage phase: pure deterministic state that every later
LLM prompt reads. All three pieces below landed; see CLAUDE.md's
"Current state" entries for v0.76.1 (emotions + mood), v0.76.2 (emotion
decay ported to C++), and v0.76.3 (layered memory v1) for the shipped
design/verification detail — kept here only as the original scoping.

- **Per-agent emotion vector** (fear/joy/grief/anger, 0..1, decaying):
  updated by existing events (deaths nearby, predator attacks,
  festivals, births, disputes, starvation) at the sites that already
  call `_remember`. Consumed by: cognition + dialogue prompts (core
  cast — free richness per call) and *small* deterministic nudges for
  everyone (a frightened agent forages closer to home; a grieving one
  socializes less). Bounded, capped, pruned on death like every other
  per-agent map (memory-leak rule).
- **Settlement mood vector** (hope/fear/grief/suspicion): aggregate of
  agent emotions + event balance, monthly `bounded_random_walk_step`
  update + event nudges — literally temperament's pattern, pluralized.
  Temperament stays as-is (Phase G's spine); mood is the *social*
  reading beside it. Biases prompts (town brain, dialogue, omens) and
  tiny deterministic rates (the Phase G "small, never-dominant" rule).
  UI: never labeled "mood" — reachable via `summary()`/dev surface
  like temperament (ambiguity discipline applies).
- **Layered memory v1**: split `Agent.memories` into
  `working` (small, fast-decaying, feeds prompts) and `episodic`
  (current capped list, unchanged serialization name for backward
  compat) + a per-memory salience score (emotion-weighted at write
  time). Forgetting = salience-weighted eviction instead of FIFO.
  Semantic layer deferred to Phase J (it needs Reflect()).
- R7 applies: emotion/mood update math is physical-substrate-adjacent
  bulk arithmetic — write the per-tick decay/aggregate pass C++-first
  with Python fallback, same discipline as every native module.

Verification: soak runs confirming bounded state + zero behavior change
with the nudges disabled; manual script dumping emotion trajectories
around a death/festival to eyeball plausibility.

### Phase J — Deeper Minds (core cast only)

- **Persistent mind schema**: extend `Agent` (dict fields, not the
  native SoA — variable-size, stays Python per v0.75.0's split) with a
  `mind` dict: permanent (values, fears, ambitions, worldview — 
  LLM-authored once at core-cast entry, genesis-style one-time call),
  slow (ideology leanings), fast (current preoccupation). Non-core
  agents get a cheap deterministic template from traits.
- **Specialized cognitive tasks, not giant prompts**: decompose the
  cognition job into narrow calls that *share the daily-cognition
  budget slot* rather than adding calls: the per-sim-day cognition
  call becomes Plan() (goal + reason, as today); **Reflect()** is new,
  weekly, staggered like monthly jobs — reads recent episodic
  memories + emotions, writes 1 semantic memory ("I have come to
  think…") + optional belief/trust nudge. Semantic memories are the
  third memory layer (small cap, high prompt priority).
- **Secrets & lies**: `Agent.secrets` (bounded list, core cast) —
  planted by Reflect()/disputes; dialogue prompt may reference or
  guard them; a rumor can *be* a leaked secret. Deterministic
  fallback: no secrets, no behavior change.
- **Mistakes stay in**: prompt language explicitly permits
  procrastination, bias, denial (extends the v0.72.1 disagreement
  permission — same lever, wider).

Verification: prompt-token measurement before/after (the v0.72.1
~786-token discipline); live-report review of Reflect() outputs.

### Phase K — Knowledge & Story (the rumor→folklore→myth pipeline)

- **Rumor distortion**: rumors get `hops` + `mutated` fields. Passing
  through a core-cast listener may fire **InterpretRumor()** (capped/
  day): the LLM rewrites the rumor as that agent would retell it
  (bias, exaggeration, misattribution). Crowd agents pass verbatim
  (free). Different NPCs remembering the same event differently now
  emerges mechanically: memory salience decay + distorted retellings.
- **Folklore condensation** (monthly, settlement-scoped): oldest
  surviving high-spread rumors + fading memories → one LLM call
  condenses into a folklore entry (capped list on Settlement, culture
  machinery). Folklore feeds dialogue/omen/chronicle prompts.
- **Historian v2**: chronicle prompt gains folklore + mood + themes
  (Phase M) and is explicitly asked to *interpret* ("the winter the
  forest demanded its due"), not summarize. Records/artifacts
  (v0.64.0) become the written layer future generations misread —
  heir memory already reads artifacts; now chronicle does too.
- **Dream engine**: monthly Dream() per core agent — symbolic, reads
  emotions/preoccupation/folklore (+ Town Consciousness symbol seed,
  Phase N), writes a dream memory (episodic, salience-weighted) +
  tiny belief/trust nudge. Dreams are never predictive, only
  interpretive — ambiguity discipline.

### Phase L — Society & Power

- **Reputation**: derived aggregate (mean trust toward agent across
  living agents, cached per-month) — no new per-pair state. Consumed
  by dispute outcomes, teaching choice, faction gravity, core-cast
  `_prominence` (already exists — extend its inputs).
- **Factions**: deterministic detection (belief-alignment + trust-graph
  clustering, monthly, cheap at ≤400 agents) → when a cluster crosses
  size/cohesion thresholds, one LLM call names/frames it (institution
  machinery: new kind FACTION beside FAMILY/COUNCIL/GUILD — reuses
  mirroring, capped at the existing institution cap). Factions bias
  disputes, council composition, fission party selection.
- **Economy depth**: debt (bounded per-pair ledger riding the existing
  trade mechanic), scarcity-driven specialization pressure (profession
  stickiness from skills — mostly exists), black-market flag on trades
  when a council price-nudge exists to defy. All deterministic; R7 →
  C++ where it's bulk math.

### Phase M — Faith & Meaning

- **Ritual → religion**: deterministic detector: repeated
  co-occurrence (festival after good harvest; shrine visits after
  deaths) promotes a tradition to a *ritual* (culture list, new kind).
  Seasonal gated LLM call may crystallize accumulated rituals + omen
  history + folklore into a **belief system** (named, tenets stored in
  the beliefs machinery, institution-mirrored). Schism: at fission or
  a lost dispute between factions holding it, one call splits it.
  Nothing predefined; no religion is guaranteed to ever form.
- **Narrative Direction** (quarterly, settlement-scoped, one call):
  reads chronicle + folklore + mood trajectory → names 1–2 active
  themes (grief, hope, decay…) stored on Settlement (capped history).
  Consumed ONLY as prompt bias for town brain, omens, chronicle,
  Dream() — it never schedules events, never scripts. It makes the
  Town Consciousness's nudges *thematically coherent*, which is the
  whole trick.

### Phase N — The Town Awake (Town Consciousness v2)

Phase G, given a memory and a will — extension, not replacement:

- **Persistent inner state** on the World/founding Settlement: bounded
  memory list (what it has noticed), a genesis-seeded personality
  (curiosity/patience/possessiveness scalars), 1–2 long-term
  objectives (LLM-revised rarely), and a **player model** (beliefs
  about the player, fed by player_standing + intervention history —
  the same beliefs shape, aimed at the player).
- **Monthly consciousness job** (one call): reads its memory, mood,
  themes, player model → chooses at most one *intervention* from a
  bounded deterministic menu: weather nudge (within the realized EMA
  range — the unreachable-threshold lesson applies), omen phrasing
  seed, dream symbol seed (Phase K hook), false-memory injection
  (rare; writes a plausible-but-wrong episodic memory), misplaced-
  object event, temperament/probability nudge. Every option has a
  mundane explanation; most months it chooses nothing.
- **Emotional contagion / synchronized experiences**: two agents
  receiving the same dream symbol or phrase in the same month — pure
  seed-sharing, free, and exactly the FROM/Higurashi register: only a
  player reading two NPC inspectors would ever notice.
- Fallback: no call → no intervention that month. `phase_g_intensity`
  scales all of it; 0.0 remains a genuine off switch.

### Continuous (no phase): C++ engine track

R7/R8 proceed unchanged and absorb the vision's performance mandate.
Phase I's emotion/mood passes are the first *new* R7 modules; the
population tick-logic port (R8's next leg) continues in parallel.
Python remains orchestration + LLM + persistence, per the R6 boundary.

## 5. Standing design tests (apply to every phase)

1. "Will this make the world feel more alive even if the player never
   interacts with it?" — if no, redesign.
2. Does it extend an existing store/job/pattern? If it needs a new
   parallel subsystem, justify in docs/DECISIONS.md first.
3. Is every new collection bounded (cap/prune/retention)? (v0.71.0
   audit rule.)
4. Is the LLM call gated (core cast or settlement-scoped + staggered
   day + backpressure) and fallback-covered?
5. Does anything label the supernatural? (Never.)
